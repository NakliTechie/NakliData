# NakliData v1.8.0 — release notes

Status: **release candidate; not tagged or deployed**. Versioning is
git-tag-based; the in-app `BUILD_VERSION` remains `0.1.0`.

## Headline — scoped Browser Agent API v3

NakliData now exposes a versioned agent surface at
`window.naklidata.v3`. It lets an external agent ground itself in the live
semantic workspace and add reviewable work without receiving execution
authority.

- Seven metadata tools describe tables/cells, report capabilities and lineage,
  export the data dictionary, and validate portable artifacts.
- One separately gated value tool runs a bounded, read-only direct projection
  with source provenance and semantic sensitivity redaction.
- Three separately gated proposal tools add editable, explicitly un-run SQL,
  chart, and quality-check cells through the same paths as the product UI.
- Every result is a structured v3 success/failure envelope with stable errors,
  scope, workspace/source provenance, bounds, redaction, and untrusted-content
  metadata.

The root Browser API v2 remains available and unchanged for compatibility.

## Permission and safety model

`metadata:read` is available for grounding. `values:read` and
`workspace:propose` require explicit per-tab grants under Settings → Agent
access. Grants are memory-only, independently revocable, clear at workspace
boundaries, and cancel affected in-flight requests. A bounded metadata-only
activity ledger records tool/outcome/timing—not SQL, values, artifact contents,
or credentials.

There is no execution scope or run-cell tool. Proposals never run themselves,
write remote data, start background polling, or bypass normal ownership and
validation. `proposeCleaningStep` remains discoverable but unavailable until
the table-context cleaning work in N5 is complete.

## Adapter status

- Browser API v2: available.
- Browser API v3: available.
- WebMCP: experimental, feature-detected, and flag-gated. Current async
  registration, same-origin exposure, structured results, rollback, and abort
  teardown are tested; browser availability is not claimed.
- External MCP: planned only. The approved future boundary is a separate
  artifact-first stdio package; no live-tab bridge or server ships in this
  release candidate.

## Verification

- 1,680 deterministic unit/integration/eval tests pass.
- Production browser smoke passes v2/v3 compatibility, all eleven tools,
  value/proposal gating, editable un-run proposal state, metadata-only
  activity, revoke/denial behavior, accessibility, graceful native WebMCP
  absence, and current-shape mock registration/teardown.
- Adversarial coverage includes malformed inputs, prompt-like headers/values,
  aliases, expressions, joins, duplicate ownership, missing sensitivity,
  cancellation, workspace replacement, proposal bounds, redaction, and
  provenance.
- The single-file app remains within the 768 KiB shell budget at 786,228 bytes.

## Build and supply-chain maintenance

- The supported development/CI floor is Node.js 22.
- Vitest, Vite, esbuild, Wrangler, and the affected transitive graph were
  upgraded after GitHub's high-severity advisory gate began rejecting the old
  lockfile.
- Narrow overrides select patched `adm-zip`, `sharp`, `protobufjs`, and `tsx`
  releases until their direct parents publish compatible patched ranges.
- `npm audit` reports zero vulnerabilities. The complete 68-spec Playwright
  suite now runs from a consistent post-onboarding test state; production smoke
  continues to verify the real first-run welcome flow.

Deployment, tagging, and publication remain separately authorized actions.
