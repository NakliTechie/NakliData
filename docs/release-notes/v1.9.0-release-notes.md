# NakliData v1.9.0 — release notes

Status: **release candidate; not tagged or deployed**. Versioning remains
git-tag-based. Publication requires separate authorization.

## Standards interoperability candidate

Five exact, bounded profiles now have dated engineering evidence:

- `naklidata-skos-2009-v1`
- `naklidata-shacl-2017-core-v1`
- `naklidata-prov-o-2013-v1`
- `naklidata-owl-2-rl-v1`
- `naklidata-bounded-standards-reasoning-v1`

The adapters use stable canonical identifiers, deterministic Turtle,
structured semantic-loss records, detached proposals, strict byte/resource
ceilings, and no network dereference. The reasoner runs in a bounded worker and
returns traceable review proposals without execution authority.

RDFLib 7.6.0, PySHACL 0.40.0, and OWL-RL 7.6.2 pass the six-file public W3C
fixture matrix. N3.js 2.1.1 and rdf-validate-shacl 0.6.5 cover the browser-side
syntax and SHACL comparison paths. Import → edit → export, namespace stability,
the v0 migration, unsupported terms, malformed Turtle, and cancellation have
deterministic regression coverage.

## Availability boundary

All five product release flags remain off. Agent capability discovery reports
the exact profiles as `release-gated` with `enabled: false`. No current tool or
navigation surface offers standards import, export, or reasoning. The release
candidate therefore makes no user-facing standards availability claim.

Each standard has an independent rollback gate. Reasoning additionally depends
on the SKOS and OWL gates. A later release must add and verify the relevant
product surface before changing one of these flags.

## Iceberg source boundary

Public Iceberg table-by-URL reads are available for HTTPS metadata files or
table directories. The generic REST card remains unavailable.

The candidate now names three exact pending profiles:

- `databricks-unity-catalog-aws`
- `snowflake-open-catalog-s3`
- `snowflake-open-catalog-gcs`

Iceberg REST requires both a dated verified profile and an independent release
flag. Both default and generated product truth remain fail-closed. Table and
REST flags are independent, so a REST rollback does not disable the verified
public-table path. Azure/ADLS remains excluded. Catalog evidence does not imply
Databricks SQL Warehouse or Snowflake Virtual Warehouse support.

See `docs/iceberg-rest-release-gate.md` for enablement, persistence,
limitations, troubleshooting, and rollback.

## Exclusions

This candidate does not claim full SKOS integrity validation, full SHACL Core,
SHACL-SPARQL, full PROV-O, full OWL 2 RL, OWL DL, JSON-LD, RDF/XML, remote
ontology imports, general rule execution, automatic enforcement, or automatic
proposal acceptance.
